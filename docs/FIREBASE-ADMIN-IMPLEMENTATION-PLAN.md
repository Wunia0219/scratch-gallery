# Firebase 後台三階段設計摘要

2026-10-08 規劃，基準版本 1.2.1。查閱完整原案可執行 `git show c84d61c:docs/FIREBASE-ADMIN-IMPLEMENTATION-PLAN.md`。三階段本機程式其後完成，第三階段保留 1.4.0 待驗收。實際連線、驗證及正式切換狀態以各階段操作指南為準。

| 階段 | 設計決定 | 操作與驗收 |
| --- | --- | --- |
| 活動後台 | 使用網站專屬 Firebase、Google 登入及啟用的 owner。草稿與公開資料分開，發布、版本與稽核同一交易提交。時程以台灣時間編輯。 | [登入、活動管理與切換](FIREBASE-ADMIN-SETUP.md) |
| 作品管理 | SB3 與封面在本機處理，檔案隨 Netlify 部署。後台管理介紹、排序、上下架及草稿還原。同一作品永久沿用 UUID。 | [資源驗證、遷移與還原](FIREBASE-WORKS-SETUP.md) |
| 投票 | 每活動使用獨立 Google 表單，每帳號限一次，不收姓名或 Email。Apps Script 完整重算，網站只接收有版本的彙總。收票狀態須由來源確認，結算後更正另建版本。 | [串接、同步、結算與 CSV](FIREBASE-VOTING-SETUP.md) |

## 部署與復原

- 新增遊戲資源、模板、播放器或後台程式需部署。修改已部署作品的介紹與公開狀態、活動時程或票數顯示可直接從後台完成。
- 每次正式部署須重新取得站主核准。新作品先部署並驗證檔案，再確認上架。部署後的公開檔案可直接開啟，須保密的作品應延後部署。
- 預覽使用獨立測試專案。Firebase 讀取失敗時隱藏活動或回報暫時無法使用，避免舊版內容重新曝光。
- 遷移前保留私有備份及已知可用版本。回復程式、作品檔案、資料與 Google 表單設定需分別核對；維持既有 UUID、首次上架日期、稽核與結算版本。
- 投票資格、獎項、截止時間、同票處理與結果公開方式由主辦方確認。Google 授權、表單建立與實票驗收另依第三階段指南完成。

測試與故障處理見 [SECURITY.md](../SECURITY.md)，發布核准與素材清理見 [AGENTS.md](../AGENTS.md)。
